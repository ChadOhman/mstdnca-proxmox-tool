Setup

Harmony is installed with its own installer (docs); this page manages upgrades and health of an existing install.

  1. Make sure the Harmony VM is listed under Guests with its IP address and an SSH credential (root, or a user with passwordless sudo — the stack's files are root-owned).
  2. Install that credential's public key in the VM's authorized_keys, then use Test connection on the guest.
  3. Select the guest above, save, then Detect Version and Check for Updates.
  4. Run Pre-flight and Health Check once to confirm the gates pass on your instance.

Upgrade Steps
  1. {% if settings.protection_type == 'backup' %} Backup (vzdump) to {{ settings.backup_storage or '(storage not set)' }} (mode: {{ settings.backup_mode or 'snapshot' }}): {% else %} Snapshot: {% endif %} {{ _app_guest.name if _app_guest else '(guest not set)' }}
  2. Harmony backup: {{ _dir }}/self-host/harmony backup --no-storage
  3. Update: {{ _dir }}/self-host/harmony update --version {{ settings.latest_version or 'X.Y.Z' }} (pulls images, migrates, recreates containers)
  4. Verify: version matches; harmony doctor --offline shows no container FAILs and passing migrations, auth, database, livekit; realtime.messages still has a SELECT policy

Other doctor checks (DNS, TLS, reachability, ports) are shown but never block: behind a tunnel or NAT they can fail permanently. Local compose overlays (COMPOSE_FILE in self-host/.env) are left as they are.
